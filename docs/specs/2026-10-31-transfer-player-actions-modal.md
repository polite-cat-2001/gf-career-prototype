# Модальное окно действий игрока (трансферы)

> Черновик на 2026-10-31. Референс — экран действий игрока FIFA 18 (скриншот в задаче).
> Цвета, шрифты и фокус — наши (тёмное стекло, лаймовый фокус), набор элементов и их
> расположение — из референса. Не реализовано.

## Зачем

С экрана результатов поиска нужен быстрый доступ к действиям по игроку, не уходя со списка:
скаутинг, шортлист, предложения и обсуждение перехода. Окно открывается поверх результатов и
показывает всё, что менеджер может сделать с выбранным игроком.

## Триггер и закрытие

- `A`/клик на карточке результата открывает окно действий для этого игрока. Фокус и выбранный
  игрок справа синхронизированы: наведение/фокус на карточке меняет правую карточку, `A`
  открывает окно.
- `B`/`Esc` закрывает окно и возвращает фокус на ту же карточку результата.
- Окно — фокус-ловушка: пока оно открыто, `D-pad` ходит только по строкам действий, `Q`/`E` и
  верхние табы не работают. `B` — единственный выход.
- Первая версия окна выводит все действия **disabled** с пометкой тикета (#14/#15/#16/#17/#19):
  сначала проверяем вёрстку и навигацию, действия подключаем по мере готовности срезов.
- После подключения действия окно остаётся открытым и обновляет строку (например, «Добавить в
  шортлист» → «Удалить из шортлиста»); для предложений/переговоров окно закрывается и
  открывается соответствующий экран.

## Расположение

Окно перекрывает левую колонку результатов (как в референсе), правая карточка игрока остаётся
видна за затемнением. На узких экранах окно центрируется.

```

│ [фото]  Имя Игрока                         КЛУБ  [герб]     │
│         25 · ПП · 178 см · нога: ?                           │
├──────────────────────────────────────────────────────────────┤
│ ОБЩ.      ?      │  Разгон                ???                │
│ ЦЕНА      ?      │  Скорость рывков       ???                │
│ ЗАРПЛАТА  ?      │  Ловкость              ???                │
│ ФОРМА     —      │  Баланс                ???                │
│                  │  Дриблинг              ???                │
│                  │  Владение              ???                │

│ ● В клубе / Свободный агент                                  │
│ ● Доступен                                                   │

│ A  Поручить {скаут 1} — следить за {игрок}                   │
```

## Элементы

### Шапка

- Фото игрока слева (крупное, без подложки, не обрезается).
- Имя крупной типографикой.
- Справа — клуб и герб (у свободного агента — «Свободный агент» без герба).
- Строка фактов: возраст, амплуа коротким кодом (`ПП`, `ЦЗ`, `ФРВ`), рост, рабочая нога.
  Рабочая нога и другие скрытые поля показываются как `?` до скаутского отчёта.

### Блок показателей

Две колонки, как в референсе:

| Слева | Справа |
|---|---|
| ОБЩ. (`?` до отчёта) | Предварительный отчёт: Разгон, Скорость рывков, Ловкость, Баланс, Дриблинг, Владение — все `???` до отчёта |
| ЦЕНА (`?`) | |
| ЗАРПЛАТА (`?`) | |
| Отступные (видимы всегда) | |

`ФОРМА` из референса заменяется на «Отступные», потому что формы внешнего игрока в данных нет.
Если появится отчёт скаута, `?` заменяются точными значениями (этот срез — #14).

### Статусные строки

Три строки с иконками, как в референсе; содержимое адаптировано под доступные данные:

- Статус: «В клубе» / «Свободный агент» / «На трансфере» / «В аренде» / «Заблокирован».
- Доступность: «Готов к игре» (когда появится состояние внешнего игрока), иначе строка скрыта.
- Контракт: «Контракт истекает через N мес.» — для игроков с истекающим контрактом. Сроки
  внешних игроков генерируются на старте карьеры (см. раздел «Сроки контрактов»).

### Список действий

Крупные вертикальные строки на всю ширину, первая — в фокусе. Между скаутингом/шортлистом и
предложениями — тонкий разделитель.

| Действие | Условие | Поведение |
|---|---|---|
| Поручить {скаут} — следить за {игрок} | По одной строке на каждого **свободного** скаута (#19). Скаутов нет — одна disabled-строка «Нанять скаута (#19)» | Назначает слежку; строка этого скаута становится «{скаут} следит» и disabled до отчёта. Занятые скауты своих строк не получают |
| Добавить в шортлист | #15 | Добавляет в шортлист; строка меняется на «Удалить из шортлиста». Шортлист хранится в карьере и переживает смену клуба |
| Сделать предложение трансфера | #16, игрок в клубе | Закрывает окно и открывает экран предложения |
| Сделать предложение аренды | #16, игрок в клубе | Закрывает окно и открывает экран аренды |
| Обсудить переход | #17, свободный агент или игрок с истекающим контрактом | Закрывает окно и открывает переговоры о контракте |

В первой версии все строки disabled с пометкой соответствующего тикета. После подключения:
для свободного агента предложения трансфера и аренды disabled с пометкой «Свободный агент»;
для игрока в клубе «Обсудить переход» disabled, если контракт не истекает.

## Состояния и визуал

- Обычная строка — тёмная плашка без заливки.
- Фокус/наведение — тот же единственный фокус: лаймовая обводка и мягкое свечение.
- Disabled — приглушённая строка с пояснением причины.
- Переключаемые строки (шортлист, слежка) меняют текст, а не цвет.
- Фон окна — наше тёмное стекло; скрим затемняет результаты и правую карточку.
- Никаких мелких кнопок: все действия — крупные строки, легенда снизу.

## Сроки контрактов внешних игроков

Проверка кода: сейчас `ensure_player_contracts` (`server/career/squad.py`) заполняет
`career.player_contracts` только для состава выбранного клуба; вызов — в
`create_career_endpoint` (`server/app.py`). Для остальных игроков канона контрактов нет ни в
`canon.db`, ни в сейве.

Решение для модального окна и поиска: генерировать сроки **на старте карьеры** детерминированно
от `career.seed + player_id`, не храня 122k записей в сейве:

- `contract_months` — 0–60 месяцев; 0 = свободный агент (совпадает с `club_id IS NULL`);
- «истекает» = `contract_months <= 6`;
- значение выводится из seed и не меняется при повторных загрузках;
- подписанные/продлённые контракты по-прежнему пишутся в `career.player_contracts` и
  перекрывают сгенерированное значение;
- поиск и окно действий получают `contract_expires` (ISO-дата или `None`).

Если позже понадобится история контрактов, сгенерированные значения можно материализовать в сейв.

## Данные и API

- В сейв карьеры добавляются:
  - `shortlist: list[player_id]`;
  - `scouting: dict[player_id, {scout_id, started_at, due}]` (когда появятся скауты);
  - позже — `offers` и сроки контрактов внешних игроков.
- Ответ поиска (`GET /api/careers/{id}/transfers/search`) расширяется полями
  `shortlisted`, `scouting`, `contract_expires` (сгенерированный срок из seed).
- Действия идут через существующий `POST /api/careers/{id}/actions`:
  `shortlist_add`, `shortlist_remove`, `scout_assign`, `offer_transfer`, `offer_loan`,
  `discuss_move`. Каждое действие сохраняет сейв и возвращает обновлённый снимок/ответ.
- Туман сохраняется: до отчёта окно не показывает OVR, статы, зарплату, ногу и стоимость;
  отступные видны всегда.

## Геймпад

- `D-pad` — строки действий; `A` — выбрать; `B` — закрыть.
- Окно не участвует в переключении разделов и табов.
- Подсказки в нижней легенде: `A` Выбор, `B` Назад.

## Принятые решения

1. Скаутов нет — строка «Нанять скаута (#19)» disabled; при появлении скаутов строки создаются
   по числу свободных скаутов.
2. Первая версия окна — все действия disabled с пометками тикетов; подключение по мере готовности
   #14–#17.
3. Сроки контрактов внешних игроков генерируются на старте карьеры из seed (раздел выше).
4. Несколько скаутов — несколько отдельных строк «Поручить {скаут}».
5. Окно всегда перекрывает левую колонку результатов; на узких экранах допускается центрирование
   без изменения состава элементов.
