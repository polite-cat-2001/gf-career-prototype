# Архитектура

Статус: **карьера играбельна в пределах сезона** — канон в SQLite, read-only API, создание карьеры с
JSON-сейвом, Svelte-экраны старта, создания, хаба, состава, плана игры, календаря, симуляции матча и
итогов тура. Работают повышение/вылет, кондиция, травмы, дисквалификации и сезонная статистика.
Поиск трансферов, скаутинг, шортлист, отправка предложений клубам, полученные предложения, мировой
AI-to-AI рынок и история трансферов работают; кубки и тренировки ещё не начаты. Канон решений — седьмая волна
`docs/specs/2026-10-21-manager-career-decisions.md`.

## Что это

Клиент-серверный веб-прототип режима карьеры менеджера. Сервер владеет миром и симуляцией, клиент —
тонкая Svelte-оболочка. Прототип проверяет две вещи: качество симуляции карьеры и удобство UX.
3D-матч и продакшн-интеграция остаются в C++-игре; прототип возвращает только `MatchOutcome`.

## Канон и API

- `canon.db` собирается командой `python scripts/build_canon_db.py` из `data/json/` и
  `ratings_output.json`. Скрипт ищет `ratings_output.json` в корне репозитория, затем в
  `../ratings-generator/output.json`; путь можно задать через `--ratings`.
- Таблицы: `meta`, `countries`, `leagues`, `clubs`, `players`, `national_teams`. У игрока —
  `overall`, `pot` и ровно 22 стата в JSON; свободные агенты получают гражданство и стоимость из
  рейтингов (`adjusted_mv`).
- `canon.db` в `.gitignore` и всегда пересобирается; ручных правок нет.
- API канона (`server/app.py`): `/api/meta`, `/api/countries`, `/api/leagues?country_id=`,
  `/api/clubs?league_id=|country_id=`, `/api/clubs/{id}`, `/api/clubs/{id}/players`,
  `/api/players/{id}`. Сервер не читает JSON и моки: только `canon.db`.
- API карьеры: `POST /api/careers` (клуб + имя/гражданство менеджера, seed генерируется, если не
  передан), `GET /api/careers` (список), `GET /api/careers/latest` (последний изменённый),
  `GET /api/careers/{id}` (снимок), `POST /api/careers/{id}/save` (ручной сейв),
  `POST /api/careers/{id}/actions` (команды: `swap` — обмен двух игроков; `advance` с `date` —
  перевести дату на день ближе к матчу; `play` — сыграть матч в день матча; `next_season` —
  начать следующий сезон после завершения; `transfer_status` — трансферный статус игрока;
  `shirt_number` — смена игрового номера; `release_player` — отпустить игрока;
  `negotiate` / `accept_counter` / `sign_contract` — продление контракта;
  `transfer_offer` / `loan_offer` — предложение клубу о покупке или аренде;
  `accept_offer_counter` — принятие контрпредложения клуба),
  `GET /api/careers/{id}/match` (pre-match: составы
  обеих команд) и `POST /api/careers/{id}/simulate` (результат + таймлайн событий).
  `GET /api/careers/{id}/transfers/search` — поиск по канону: имя, группа позиции (`GK`/`DEF`/
  `MID`/`FWD`), конкретное амплуа, возраст, гражданство, страна, лига, клуб, статус, нога и рост
  (пустой фильтр допустим); сортировки по возрасту, OVR, имени, позиции, стоимости и зарплате;
  `limit`/`offset` без пагинации. Создание
  сразу пишет JSON в `saves/` — первый автосейв. У карьеры есть `league_id` и `league_club_ids`:
  дивизион и его состав, которые меняются при повышении/вылете и не теряются между сезонами.
- Сезон — `server/career/season.py`: при создании строится double round-robin календарь лиги
  (круговая ротация, чётность добивается bye) от `season_start` (1 июля), даты — недельные.
  Дома/гости чередуются по турам, у каждого клуба ровно `n-1` домашних и `n-1` гостевых матчей.
  Сейв хранит `schedule` (id, тур, дата, home/away) и `results` (счёт по fixture id). Старые сейвы
  с `schedule_version < 2` при загрузке получают исправленные home/away для несыгранных туров;
  результаты и уже сыгранные матчи не меняются. Действие `play` разрешено только в день матча,
  симулирует весь тур и переводит дату на день после матча: сила клуба — средний OVR топ-11
  состава, ожидаемые голы зависят от отношения сил и домашнего преимущества, счёт —
  пуассоновская выборка с RNG `seed + fixture_id`. Детерминированность сохраняется.
- Матч-таймлайн — `server/career/match.py`: собирает состав из 11 стартовых и 7 запасных,
  генерирует голы (включая пенальти и ассисты), жёлтые/красные карточки, травмы с типом/сроком и
  замены, сохраняя соответствие счёту. События упорядочены по минуте, игроки для событий
  выбираются из активного состава на эту минуту; RNG — `seed + fixture_id + timeline`.
- Кондиция — `server/career/condition.py`: `player_state` хранит усталость, травму (`type`,
  `until`), дисквалификацию (`matches`, `reason`) и сезонные `apps/starts/minutes/goals/assists/
  yellow/red/clean_sheets`. Те же показатели дублируются по турнирам в
  `stats_by_competition` (ключ — id турнира, сейчас лига); сухой матч получает стартовый вратарь
  при нуле пропущенных. Старые сейвы при первом снимке получают разбивку из суммарной статистики.
  Стартовые получают −35 усталости, вышедшие на замену −15, восстановление +4 в день;
  при недельном календаре это оставляет остаточную усталость после нескольких матчей подряд.
  Травма блокирует выбор, красная и 5-я жёлтая дают дисквалификацию на матч. Недоступного
  стартового заменяет лучший доступный по близости позиции (вратаря — запасной вратарь), а травма
  по ходу матча принудительно меняет игрока на ближайшего по позиции. `lineup_strength` считает
  силу по выбранному XI с учётом усталости, а не по топ-11 канона.
- Контракты и настрой — `server/career/squad.py`: при создании карьеры каждый игрок получает одно
  из пяти амплуа по рангу OVR в составе (`85/65/45/25/10%` ожидаемого игрового времени), срок
  1–5 лет по возрасту, недельную зарплату от стоимости и возраста и отступные `1.2–2.0 ×`
  стоимости. Значения детерминированы `seed + player_id` и пишутся в `player_contracts`; старые
  сейвы получают их при первом снимке. Настрой = фактические минуты к ожидаемым: после каждого
  матча доступным игрокам (без травмы и дисквалификации на старте) начисляется
  `90 × доля амплуа` в знаменатель, поэтому пропущенные из-за травмы/бана матчи его не раздувают;
  сброс сезона очищает знаменатель вместе со статистикой.
- Финансы — там же: `player_values` хранит стоимость каждого игрока, `player_ages` — возраст,
  `balance` — баланс клуба `0.25 ×` суммарной стоимости состава (не меньше 1 млн). В течение
  сезона стоимость неизменна; при `next_season` пересчитывается от стоимости, возраста (+1 год),
  OVR и минут к ожидаемым, затем возраст и новая стоимость пишутся обратно в сейв. Снимок отдаёт
  `squad.finance` (баланс, стоимость состава, недельная ведомость) и обновлённые
  `market_value`/`age` игроков.
- Предложения клубам — `server/career/transfers.py`: `transfer_offers` хранит отправленные
  офферы (`id`, `player_id`, `kind` = `transfer`/`loan`, сумма, `loan_fee` и `wage_share` для
  аренды, `buyout`, `status`, `due`, `counter_offers`, `counter`, `retry_after`, `message`).
  Валидация: игрок существует в каноне, не свой, сумма не отрицательна и не выше баланса,
  выкуп по отступным доступен только для игрока с клубом и известными отступными, активный оффер
  по игроку не дублируется. Ответ клуба детерминирован `seed + id` оффера и приходит через 2–4
  дня, когда дата доходит до `due`; при сравнении со стоимостью/отступными AI принимает,
  отказывает или даёт контрпредложение (до двух). По игроку хранится один оффер: новый оффер
  заменяет прежний, а оффер с контрпредложением пересобирается на месте с сохранением счётчика;
  после отказа повтор разрешён через 7 дней (`retry_after`). `accept_offer_counter` принимает
  новые условия; принятый оффер открывает переговоры о личном контракте игрока, а входящие
  предложения — следующий срез. Отозвать отправленный оффер нельзя.
- Контракт игрока — `server/career/transfer_contracts.py`: `transfer_contracts` хранит требования
  игрока (`demand`), предложение, контрпредложение, согласованные условия, статус, дату ответа и
  fee/условия аренды; `pending_transfers` — подписанные переходы, ждущие окна. Спрос детерминирован
  `seed + player_id`; контрпредложение раскрывает точные зарплату, срок, амплуа и отступные.
  Подписание проверяет баланс, списывает fee, пишет контракт и номер в сейв; при открытом окне
  игрок сразу попадает в состав (оффер сразу уходит из «Отправленных»), иначе ждёт и
  добавляется при открытии окна, после чего оффер удаляется из «Отправленных».
- Входящие предложения — `server/career/incoming_offers.py`: `incoming_offers` хранит офферы
  AI-клубов по игрокам менеджера (`club_id`, `kind`, сумма, `demand`, статус, `created_at`,
  `expires_at`, `due`, `counter`, `acknowledged`). Генерация детерминирована `seed` и идёт по
  дням на `advance`/загрузке от `incoming_market_date`: в окне 1–2 оффера на скользящие 7 дней,
  вне окна 1 на 14 дней, не больше 2 новых в день; в последний день окна дневного лимита нет
  (3–5 офферов). Игрока выбирает взвешенный случай: выставленные на трансфер/аренду, истекающие
  контракты и топы по OVR/статистике чаще; заблокированные не получают офферов. Клуб-покупатель
  выбирается по потребности в позиции (`club_role_stats`: число и лучший OVR по роли), иностранные
  клубы — только для игроков с OVR ≥ 75. Активный оффер от одного клуба по игроку не дублируется,
  но другие клубы могут претендовать на того же игрока. Оффер живёт 30 дней. Действия:
  `incoming_accept` (при окне игрок сразу уходит и fee идёт в баланс, вне окна — в
  `pending_departures` до открытия окна), `incoming_refuse`, `incoming_counter` (одно
  контрпредложение, ответ AI через 2–4 дня) и `incoming_ack` (снимает бейдж непрочитанного).
  Принять оффер нельзя, если в составе останется меньше 11 игроков.
- Мировой AI-to-AI рынок — `server/career/world_market.py`. Окно (июль–август или январь)
  прогоняется четырьмя пакетами: открытие, середина, последняя неделя, последний день; даты
  сделок распределяются внутри периода пакета. На каждом пакете детерминированная выборка
  AI-клубов (до 120) продаёт 0–3 и покупает 0–3 игроков за окно, не выходя из состава 18–30 и
  бюджета 10% стоимости состава (без уже купленных в это окно). Потребности в ролях считаются на
  лету из текущего состава и в сейв не пишутся. Сделки — только прямые трансферы без переговоров,
  аренд и отступных: покупатель сразу платит цену не ниже стоимости игрока. Свободные агенты
  подписываются за 0. Клуб менеджера в рынке не участвует. Составы меняются дельтами
  `club_deltas` (`in`/`out` по клубам), история сделок — `world_transfers` (цена, клуб-продавец и
  покупатель, OVR на момент перехода, дата); `world_market_date` отмечает обработанный день.
  `effective_players` накладывает дельты на канон и используется силой соперников, составами в
  матче и ранжированием дивизионов.
- Действия центра составов — `server/career/actions.py` и `squad.py`: у каждого игрока есть
  взаимоисключающий трансферный статус (`transfer` / `loan` / `blocked`, повторное нажатие
  снимает), уникальный номер 1–99 из `shirt_numbers` (канонический номер, если свободен, иначе
  первый свободный) и переговоры о продлении в `negotiations`. Переговоры хранят требования
  игрока (`demand`), число контрпредложений (до двух), текущее предложение, дату ответа (`due`) и
  флаг прочтения (`acknowledged`). После предложения игрок думает 2–4 дня: при `advance`/загрузке,
  когда дата дошла до `due`, он принимает, если предложение закрывает требования по зарплате,
  сроку, амплуа и вилке отступных `1.2–2.0 ×` стоимости, иначе даёт контрпредложение или после
  двух отказов прекращает переговоры; ответ помечается непрочитанным. `accept_counter` принимает
  условия игрока и сразу подписывает контракт, если клуб может покрыть новый месячный фонд
  зарплат (`недельная ведомость × 4 ≤ баланс`), иначе условия принять нельзя. `ack_negotiation`
  снимает бейдж, `sign_contract` вручную применяет условия предложения, которое игрок принял.
  `release_player` удаляет игрока из состава, заявки,
  амплуа/статусов и запрещён, если в составе останется меньше 11 игроков. Весь прогресс
  детерминирован `seed` и пишется в журнал.
- Поиск трансферов — `Canon.search_players` строит SQL по `players` с join клубов, лиг и стран;
  группа позиции маппится на коды ролей (`GK`; `CB/LB/RB`; `DM/CM/LM/RM/AM`; `CF`), возраст
  считается от даты карьеры, зарплатная сортировка — от стоимости и возрастного коэффициента. Ответ отдаёт только базовые данные (имя, возраст, рост, позиция, гражданство,
  клуб, лига, страна, статус, фото) и сумму отступных из контракта/детерминированной формулы
  `1.2–2.0 ×` стоимости; OVR, потенциал, статы, зарплата, рабочая нога и стоимость в ответ не
  попадают, пока игрок не изучен. Если скаутинг раскрыл игрока, ответ помечает `scouted: true`
  и добавляет `overall`, `pot`, `stats`, `weekly_wage`, `foot` и `market_value`. Статус `free` —
  игрок без клуба, остальные — из `player_transfers`. Поиск читает
  только канон и сейв, ничего не пишет. Для внешних игроков срок контракта не хранится: остаток
  в 1–60 месяцев детерминирован `seed + player_id`, свободный агент получает `None`, подписанный
  контракт перекрывает расчёт (`years × 12`); дата `contract_expires` отсчитывается от даты
  создания карьеры, поэтому не меняется при повторных загрузках.
- Скаутинг — `server/career/scouting.py`. В карьере шесть слотов, на старте наняты двое;
  кандидаты и их цена детерминированы пулом от `seed` (звёзды «Опыт»/«Решение», цена).
  Найм списывает цену с баланса и занимает слот. У скаута одна сетевая задача (регион → страна
  + критерии `role/age/contract`) и не больше одного активного отчёта по игроку одновременно;
  сеть и отчёт могут идти параллельно. Отчёт длится `6 − Опыт` дней (1–5), блокирует скаута для
  новых отчётов и игрока для других скаутов; после завершения отчёта скауту можно поручить
  нового игрока.
  Сеть ежедневно на `advance` находит 1–3 игроков (зависит от «Решения»), до 20 на задачу;
  найденные и завершённые отчёты образуют множество `scouted`, раскрытое в поиске и карточках.
  Задача редактируется (позиция, возраст, контракт) и сохраняется автоматически. Готовые отчёты
  и рекомендации попадают в виджет хаба; удаление убирает игрока из списка, не отменяя задание.
  Действия API: `scout_hire`, `scout_assign`, `scout_network`, `scout_task`, `scout_remove`,
  `scout_ack`; прогресс тикает на `advance`, детерминирован `seed` и пишется в журнал.
- Модальное окно действий игрока — общий клиентский компонент `PlayerActionsModal.svelte`
  (поиск и «Отчёт скаута»): открывается `A`/кликом на карточке, перекрывает экран скримом; фон
  получает `inert`, фокус заперт на строках, `Q`/`E` и табы не работают, `B`/`Esc` закрывает и
  возвращает фокус на карточку. В поиске у неразведанного игрока OVR, статы, зарплата и нога
  скрыты, у отчёта — раскрыты. «Поручить скауту» открывает пикер свободных скаутов; остальные
  строки (шортлист, предложения, обсуждение) disabled с тикетами #15/#16/#17. Список действий
  не скроллится: все строки помещаются в окно.
- Снимок отдаёт `season.last_matchday`: все результаты завершённого тура, таблицу после тура и
  `delta`/`previous_position` для каждого клуба. Таблица «до тура» считается исключением всех
  матчей этого тура; в первом туре дельты нулевые.
- Время двигается только серверным действием `advance`: клиент анимирует дни по 1 в секунду, но
  каждая остановка (кнопка, день матча, `Esc`) отправляет дату на сервер и сохраняется. Перескочить
  день матча нельзя; `play` до дня матча отклоняется. `next_season` доступен только после
  последнего тура: архивирует итог в журнал, сдвигает `season_start` на год, пересобирает
  календарь, меняет состав дивизиона и очищает `results`.
- Переход сезона (`season_transition`) считает итоговую таблицу дивизиона, 3 места повышения и
  3 места вылета, определяет перемещение клуба и состав следующего дивизиона. Соседние дивизионы
  ранжируются по силе составов; для нового дивизиона отдаются списки `from_above`/`from_below`
  (кто пришёл из лиги выше и ниже) и ссылки `above`/`below`. Снимок получает `season.review` с
  таблицей, зонами и переходом; `next_season` применяет тот же расчёт и сохраняет новый
  `league_id`/`league_club_ids`.
- Снимок отдаёт `season`: `season_start`, `next` (соперник, дата, тур, дома/в гостях, сила),
  `last_result` (счёт, исход W/D/L), `form` (до 5 последних матчей), полную таблицу
  (`standings`: очки, разница, место) и `review` на завершённом сезоне (итоги, повышение/вылет,
  переход в новый дивизион). Старые сейвы без `schedule`/`results` валидны: календарь строится
  лениво и записывается при первом действии.
- Сейв — дельта: `version`, `id`, `seed`, `date`, `season_start`, `manager`, `club_id`,
  `league_id`, `league_club_ids`, `player_ids`, `lineup` (необязательный порядок стартовых 11),
  `bench` (необязательный порядок запасных), `schedule`/`schedule_version`/`results` (сезон),
  `player_state` (усталость, травмы, дисквалификации, сезонная статистика, разбивка по турнирам и
  знаменатель настроя),
  `player_contracts` (амплуа, срок, зарплата, отступные), `player_values` (стоимость),
  `scouts`/`scout_assignments`/`scout_tasks`/`scout_reports`/`scout_found`/`scout_networks`
  (скаутинг; старые сейвы получают двух скаутов лениво при первом снимке или действии),
  `player_ages` (возраст на текущий сезон), `player_transfers` (трансферные статусы),
  `shirt_numbers` (игровые номера), `negotiations` (переговоры о продлении), `transfer_offers`
  (отправленные предложения клубам), `transfer_contracts` (переговоры о личном контракте игрока),
  `pending_transfers` (подписанные переходы до открытия окна; старые сейвы получают пустые
  списки), `incoming_offers` (входящие предложения AI-клубов), `pending_departures` (принятые
  вне окна уходы игроков), `incoming_market_date` (последний обработанный день рынка; старые
  сейвы начинают с текущей даты), `world_market_date` (последний обработанный день мирового
  рынка), `world_transfers` (история AI-to-AI сделок и подписаний свободных агентов),
  `club_deltas` (дельты составов AI-клубов `in`/`out`; старые сейвы получают пустые значения),
  `transfer_history` (завершённые сделки менеджера с ценой и рейтингом на момент перехода),
  `shortlist`
  (игроки «на карандаше»; старые сейвы получают пустой список), `balance`, `condition_date`,
  `journal`, `created_at`/`updated_at`.
  Клуб и атрибуты игроков не дублируются — читаются из `canon.db` при загрузке. Сейвы без
  `lineup`/`bench` валидны: стартовые выводятся из `player_ids` по схеме 4-3-3, запасные — по
  OVR. Старые сейвы без `player_state` получают усталость 100 и нулевую статистику. `version`
  сейва ≠ 1 даёт HTTP 409 с текстом «migrations are not available»; такие файлы видны в списке как
  несовместимые.
- Снимок карьеры уже содержит `club`, `manager`, `squad.groups` (по ролям, каждый игрок с 22
  статами и разбивкой `competition_stats`), `squad.summary` (размер, средний OVR/возраст,
  суммарная стоимость), `squad.finance` (баланс, стоимость, недельная ведомость),
  `squad.lineup` (схема 4-3-3: 11 слотов с координатами и игроками +
  запасные в сохранённом порядке), `season`, `scouting` (скауты, кандидаты, отчёты,
  рекомендации, сети, регионы и счётчики «Новое/Обновления») и `transfers` — данные центра
  трансферов: `shortlist` с раскрытием как в поиске и полями `scouting_state`/
  `scouting_days_left`/`negotiation_status`, `sent_offers` с карточкой игрока и текущим
  оффером/ответом (`status`, `due`, `counter`, `message`,
  `can_accept_counter`, `can_offer_again`), отсортированные по дате отправки (последний сверху),
  `received_offers` с карточкой своего игрока, клубом-покупателем и оффером (`status`,
  `created_at`, `expires_at`, `due`, `counter`, `message`, `unread`, `can_accept`,
  `can_refuse`, `can_counter`, `execute_on`), отсортированные по дате получения (новые сверху),
  а также `listed`/`loaned` — свои игроки со статусами `transfer`/`loan` из `player_transfers`.
  Поиск дополнительно помечает каждого игрока `shortlisted`. В `lineup` каждый игрок приходит со `stats` (22
  стата), `fatigue`, `effective_overall`, `injury`, `suspension`, `season_stats` и `available`;
  недоступные стартовые автоматически заменяются лучшими доступными. `lineup.bench` — до 7
  заявленных запасных, `lineup.reserve` — остальные; резервные игроки тоже выбираются и
  обмениваются, но пока остаются ниже заявки, в матч не попадают. Каждый игрок состава также
  несёт `squad_role`/`squad_role_label`, `expected_share`, `actual_minutes`, `expected_minutes`,
  `morale` и `contract` (`years`, `weekly_wage`, `release_clause`). `competition_stats` — список
  турниров с `id`, `name`, играми, голами, ассистами, минутами, карточками и сухими матчами.
  Клиент только форматирует числа и рисует поле.
- Фронтенд собирается в `web/dist`, и `server.py` раздаёт его с `/`; `/raster` — статика.
- Фото игроков: `/raster/players_faces_cutout/{id}.png` — вырезанные из GameplayFootball
  (`data/databases/default/faces`); если файла нет, API отдаёт TM-фото `/raster/players_faces/{id}.jpg`.
- `pytest` проверяет количества канона, 22 стата, обогащение свободных агентов, фильтры
  «страна → лига → клуб», состав выбранного клуба, `create → save → load → snapshot`, порядок
  списка/`latest`, отказ при несовпадении `version`, календарь double round-robin с балансом
  дома/гости, шаг даты и запрет перескочить день матча, симуляцию тура и его детерминированность
  по seed, дату «день после матча», таблицу после тура, ленивый календарь старых сейвов,
  исправление home/away у старых календарей, старт нового сезона, составы 11+7, детерминированный
  таймлайн, соответствие голов счёту, статистику/усталость после матча, травмы и дисквалификации,
  восстановление по дням, замену недоступного стартового, влияние усталости на силу и дельты
  турнирной таблицы по итогам тура. Отдельно проверены пять амплуа по иерархии OVR, доли
  ожидаемых минут, настрой `факт / ожидаемо`, исключение травмированных и дисквалифицированных
  из знаменателя, сброс знаменателя на новый сезон, контракты у старых сейвов, разбивку
  статистики по турнирам, сухие матчи вратаря, восстановление разбивки у старых сейвов и её
  сброс на новый сезон. Отдельно проверены диапазон отступных, суммарные стоимость и зарплатная
  ведомость, неизменность стоимости внутри сезона и её пересчёт от возраста/OVR/минут при смене
  сезона. Отдельно проверены взаимоисключающие трансферные статусы и их сохранение, уникальные
  номера 1–99 и запрет занимать чужой номер, удаление игрока из всех списков состава и запрет
  отпускать ниже 11 игроков, а также переговоры о продлении: предложение уходит в ожидание на
  2–4 дня, ответ появляется только к дате `due`, бейдж снимается подтверждением, до двух
  контрпредложений, отказ после них, принятие контрпредложения и ручное подписание. Поиск
  трансферов проверен на пустой фильтр и первую страницу, `limit`/`offset` без повторов, фильтры
  по имени, группе позиции, позиции, стране, лиге, клубу, возрасту, ноге, росту и свободным
  агентам, сортировки (включая скрытые OVR/стоимость/зарплату) и отсутствие скрытых полей в ответе.
  Срок контракта внешних игроков проверен на детерминированность, наличие будущей даты и `None`
  у свободных агентов. Скаутинг проверен отдельно: двое стартовых скаутов и шесть слотов, найм
  со списанием бюджета и удалением кандидата, блокировки «скаут занят»/«игрок уже изучается»,
  срок отчёта от «Опыта», завершение по `advance`, раскрытие OVR/статов/зарплаты/ноги в поиске,
  сеть находит рекомендации, критерии задачи обновляются, удаление убирает игрока из списка,
  `scout_ack` сбрасывает счётчик «Новое». Шортлист проверен отдельно: добавление, удаление и
  переключение идемпотентны, неизвестный игрок даёт 422, флаг `shortlisted` появляется в поиске,
  список переживает загрузку сейва и `next_season`, а центр трансферов отдаёт шортлист и
  статусы `transfer`/`loan`. Предложения клубам проверены отдельно: отправка трансфера и аренды
  попадает в `sent_offers`, валидация неизвестного/своего игрока, отрицательной суммы и суммы
  выше баланса даёт 422, дубликат активного оффера запрещён, ответ AI приходит только к `due` и
  детерминирован, даёт accept/refuse/counter, выкуп по отступным принимается, после двух
  контрпредложений — отказ, повтор только через 7 дней, принятие контрпредложения, замена
  прежнего оффера новым и сортировка «последнее сверху», сохранение офферов после load и
  `next_season` и загрузка старых сейвов без поля. Входящие предложения проверены отдельно:
  темп 1–2 в неделю окна и 1 в две недели вне окна, отсутствие дневного лимита в последний
  день, иностранные клубы только при OVR ≥ 75, срок жизни 30 дней, принятие внутри окна с
  удалением игрока и зачислением fee, отложенный уход вне окна до открытия, одно
  контрпредложение с ответом через 2–4 дня и бейдж непрочитанного ответа. Мировой рынок проверен
  отдельно: четыре пакета окна с непересекающимися периодами и датами сделок внутри своего
  периода, лимиты 0–3 покупки/продажи на окно, состав 18–30, бюджет 10% стоимости, подписание
  свободных агентов за 0, дельты `club_deltas` в сейве и рост/падение силы соперника в снимке
  после изменения дельт, а также загрузка старых сейвов без полей рынка. История трансферов
  проверена отдельно: мировые сделки и свободные агенты с ценой `0`, отправленный оффер в
  истории с фиксированным рейтингом, фильтры `all/league/club` (неизвестный фильтр — 422),
  запись о подписании свободного агента с ценой `0` и сортировка по рейтингу по убыванию;
  `transfers.history` переживает save/load.

## UI/UX

- Figma — визуальная правда:
  https://www.figma.com/design/sFScRV2E8CycOIf6qW2WQf/Untitled (карьера, выбор клуба, состав, главная).
- **Один фокус на экран.** Управление — геймпад (как в EA FC) или клавиатура; на экране ровно один
  `[data-nav]:focus`, остальные элементы — контекст. **Hover = selected:** наведение мыши переводит
  тот же фокус, отдельного hover-состояния нет. Меню — верхние табы, переключение `L1`/`R1`
  (`Q`/`E` на клавиатуре).
- **Нижняя легенда** показывает подсказки последнего устройства: `A`/`B`/`L1`/`R1`/`Y` или
  `Enter`/`Esc`/`Q`/`E`/`R`/`S`. Ввод определяется в `web/src/lib/input.js`, действие — в
  `actions.js`. `R` открывает подробности игрока в плане игры; `Y` на экране поиска трансферов
  переключает список и сетку. Обработчики `actions.js` лежат стеком: активный экран перекрывает
  хаб, при размонтировании возвращается предыдущий.
- **Экраны:** старт (3 крупные карточки «Продолжить / Новая игра / Загрузить»), загрузка (список
  карьер), новая карьера (страна → лига → клуб-карусель → менеджер), хаб FIFA 18 (табы «Центр»,
  «Состав», «Трансферы», далее «Офис / Сезон» со статусом «скоро»).
  - «Центр» — журнальная сетка виджетов FIFA: «Далее» (месяц и дни, календарь — #3), «Центр
    трансферов» (большой блок, #4), «Таблицы» (#3), «Срочные новости» (#4), «Тренировка» (#4).
    Виджетов «Состав» и «Лидеры состава» нет: состав открывается верхним табом.
  - «Состав» — обзор: слева крупная карточка «{клуб}: по умолч.» с полем, справа сетка 2×3 из
    плиток FIFA: «Состав клуба» (выбранная, с гербом и галочкой; это индикатор клуба, а не переход),
    «Сборная» (disabled), «Центр составов», «Выбор состава сборной», «Основные составы», «Изменить
    игрока» (все неготовые — disabled). `A` на карточке клуба открывает «План игры», `A` на
    «Центре составов» — одноимённый экран.
  - «Центр составов» — отдельный экран поверх хаба: главные табы карьеры скрыты, остаются бренд и
    клубная строка. Верхние вкладки «Статус / Статистика / Характеристики / Финансы» (`L1`/`R1`).
    Список состава слева общий для трёх вкладок, карточка игрока
    справа следует за фокусом; список скроллится внутри панели. «Статус» — фото, амплуа и OVR,
    настрой смайликом (улыбка / нейтральный / грустный) с процентом и фактическими/ожидаемыми
    минутами, личные данные, контракт (амплуа, срок, недельная зарплата, отступные) и доступность
    (травма, дисквалификация или «Готов к игре»). «Статистика» — суммарные игры, голы, ассисты и
    минуты в строке игрока; справа итог сезона и разбивка по турнирам с голами, ассистами,
    жёлтыми/красными и сухими матчами у вратарей. «Характеристики» — четыре страницы:
    «Общая информация» (позиция, возраст, амплуа, настрой, финты и слабая нога звёздами,
    потенциал, стоимость, контракт и значения шести осей радара), «Ментальные», «Физические» и
    «Технические», плюс сам радар. Страницы листает FIFA-пейджер (стрелки, круг `R` и точки);
    он не входит в фокус: `←`/`→` или правый стик переключают страницы, не снимая фокус с игрока,
    стрелки кликаются мышью. «Финансы» — сверху баланс клуба, стоимость состава и недельная
    зарплатная ведомость, ниже таблица игроков с фото: позиция, имя, возраст, стоимость, зарплата и
    срок контракта. Справа — карточка выбранного игрока с фото, амплуа, OVR, настроем, стоимостью,
    зарплатой, отступными, сроком и амплуа контракта, доступностью и кондицией. Фокус и навигация
    работают с клавиатуры и геймпада.
  - Действия центра составов — раскрывающаяся панель под строкой игрока, доступная на всех
    вкладках («Статус», «Статистика», «Характеристики», «Финансы»): три колонки «Трансфер /
    Состав / Контракт» в духе FIFA. Панель раскрывается и сворачивается анимацией, открыт только
    один игрок. Пока панель открыта, фокус заперт внутри неё: стрелки ходят только по пунктам
    панели, `Q`/`E` и вкладки не переключаются; выйти можно только `B`/`Esc` (фокус вернётся на
    строку) или повторным кликом по строке. Если строка у края списка, скролл плавно доезжает так,
    чтобы строка и панель были видны целиком.
    «На трансфер», «Добавить в аренду» и «Блокировать» взаимоисключающие: выбранный статус меняет
    текст пункта («Снять с трансфера», «Убрать из аренды», «Разблокировать»), без заливки, и фокус
    остаётся на нажатом пункте. «Рук-во командой» открывает план игры и фокусирует игрока на поле,
    в запасе или резерве.
  - «Смена номера» — отдельный экран в духе FIFA: крупная футболка, `←`/`→` листают только
    свободные номера 1–99, `A` сохраняет, `B` возвращает. «Отпустить игрока» — экран подтверждения
    с крупными вертикальными действиями. «Продление контракта» — полноэкранный экран: слева

    `↑`/`↓` циклично меняют цифру, `A` подтверждает (отдельной кнопки нет). После предложения
    игрок думает 2–4 дня; готовый ответ помечает игрока в списке и пункт «Продление контракта»
    бейджем `!`, который снимается при открытии. Крупные строки снизу предлагают условия;
    принятие контрпредложения сразу подписывает контракт (если хватает денег), а предложение,
    которое принял игрок, подтверждается кнопкой «Подписать». Подсказки управления видны в нижней легенде на каждом экране.
  - «Трансферы» — хаб как в FIFA 18: слева блок «Отчёты скаутов» со счётчиками
    «Новое / Обновления» и сеткой плиток 2×3 (6 на страницу): завершённые отчёты по запросу и игроки,

    (мин/макс), «Позиция и амплуа» (одна плитка с двумя переключателями), «Гражданство»,
    «Страна», «Трансферный статус», «Лига», «Клуб». Два уровня фокуса: `D-pad` ходит по плиткам;
    `A` входит в плитку (режим редактирования), `B`/`A` выходят обратно в режим выбранной плитки,
    после чего `D-pad` снова ходит по плиткам. Внутри плитки `←`/`→` листают значение, `↑`/`↓`
    переключают строку (мин/макс, позиция/амплуа). Плитка всегда показывает текущее значение
    по центру плашки: у гражданства, страны, лиги и клуба — крупная картинка сверху (флаг или
    логотип) и название под ней; размер картинки и шрифта привязан к ширине плитки через
    container query (`cqw`), поэтому на больших экранах они растут вместе с плиткой. Амплуа
    показывается коротким кодом (`ВРТ`, `ЦЗ`, `ЛЗ`, `ФРВ`) без отдельного бейджа. В режиме редактирования добавляются кликабельные стрелки `‹`/`›`,
    списков предыдущих и следующих вариантов нет. Вне редактирования — та же плашка без стрелок
    и без цветового выделения строки. Плитки «Лет» и «Позиция и амплуа» — две строки со своими
    стрелками, активная строка подсвечена; длинные названия переносятся на две строки. `X` —
    сброс, `Y` — начать поиск.
    «Люб.» означает отсутствие границы; для клуба сначала нужна лига.
  - Ввод имени — модальная экранная клавиатура: QWERTY-сетка крупными клавишами, `Пробел`,

    не прыгал. `B`/`Esc` закрывает без применения.
  - «Результаты поиска» — отдельный экран без верхней плашки и без табов групп; общий компонент
    `TransferPlayers.svelte` для поиска и «Списка» центра трансферов. В сетке две колонки карточек:
    фото слева, прижато к нижнему краю плитки, без подложки и без обрезки; справа имя, крупные
    возраст и амплуа, герб клуба в правом верхнем углу; догрузка при скролле и у последних строк.
    `Y` переключает сетку и одноколоночный список; выбранный игрок остаётся подсвеченным.
    Справа карточка игрока: крупное фото без обрезки, имя,
    возраст/рост/амплуа/статус, клуб с гербом в правом верхнем углу, сумма отступных с
    вертикальным центрированием и два блока отчёта — «Не изучается» и «Предварительный отчёт» с
    закрытыми `???` характеристиками. `B` возвращает к фильтрам. Пока игрок не изучен, OVR, статы,
    зарплата, рабочая нога и стоимость не показываются; после отчёта или рекомендации вместо тумана
    выводятся значения, а статус меняется на «Отчёт готов». `A`/клик по карточке открывает окно
    действий игрока: шапка с фото,
    клубом/гербом и фактами, две колонки показателей (слева ОБЩ./цена/зарплата и отступные,
    справа шесть характеристик), статус, строка «Контракт истекает через N мес.» при сроке ≤6
    месяцев. «Поручить скауту» открывает пикер свободных скаутов: занятые отчётом disabled,
    у остальных видны опыт и решение; выбор сразу создаёт отчёт. Строка шортлиста переключает
    «Добавить в шортлист» / «Убрать из шортлиста»; «Сделать предложение трансфера» и «Сделать
    предложение аренды» открывают экран предложения клубу. Если клуб уже принял оффер, обе строки
    заменяются на «Переговоры по контракту» (а после подписания — на надпись «Переход завершён ·
    присоединится {дата}»).
    «Обсудить переход» активен только для свободного агента или игрока с контрактом, истекающим в
    ближайшие 6 месяцев, и открывает экран личного контракта, пропуская экран клуба. Поиск и
    «Отчёт скаута» открывают один и тот же `PlayerActionsModal` с одинаковым набором действий:
    статус оффера (`latest_offer`) приходит в карточке игрока в обоих снимках.
  - «Центр трансферов» — отдельный экран поверх хаба: хлебные крошки, верхние вкладки «Список /
    Отправленные предложения / Полученные предложения / На трансфере / На аренде» (`L1`/`R1`),
    табы карьеры скрыты. «Список» — общий компонент результатов с шортлистом, статусом скаутинга
    и переговоров в карточке; `Y` переключает сетку и список. «На трансфере» и «На аренде» —
    свои игроки со статусами из центра составов. «Отправленные» — карточки офферов со статусом,
    датой ответа, суммой или контрпредложением и сообщением клуба, последнее предложение сверху;
    `A`/клик открывает модальное
    окно предложения в стиле окна действий игрока. Действия зависят от статуса: у контрпредложения —
    «Принять контрпредложение» (`can_accept_counter`) и «Отправить новое предложение», у отказа —
    «Отправить повторное предложение» (`can_offer_again`), у принятого — активные «Переговоры по
    контракту» (после подписания — надпись «Переход завершён · присоединится {дата}» и удаление
    оффера из «Отправленных» после присоединения). Статус и дата
    ответа — обычный текст, а не кнопки; при ожидании ответа
    действий нет. `B`/`Esc` закрывает окно и возвращает фокус на карточку. Отозвать оффер нельзя.
    «Полученные предложения» — карточки офферов AI-клубов по своим игрокам: клуб-покупатель,
    сумма/аренда, статус, срок действия, ответ на контрпредложение и сообщение; непрочитанные
    подсвечены, на вкладке счётчик-бейдж. `A`/клик открывает `IncomingOfferModal.svelte` с
    действиями «Принять предложение / Контрпредложение / Отказать»; контрпредложение вводится на
    общем экране суммы по разрядам, ответ приходит через 2–4 дня, при открытии окна игрок сразу
    уходит из состава, вне окна — при открытии окна. `B`/`Esc` закрывает окно.
  - «Предложение клубу» — отдельный экран поверх поиска/центра/отчёта скаута: слева карточка
    игрока (фото `contain`, клуб, отступные), баланс клуба; справа условия. Сумма и плата за
    аренду меняются степпером `←`/`→`, `A` открывает точный ввод по разрядам (тот же экран суммы,

    «Выкуп по отступным» с суммой отступных. Один фокус, `B` возвращает, после отправки экран
    закрывается и открываются «Отправленные предложения»; ответы и новые условия показываются
    только там.
  - «Контракт игрока» — отдельный экран после согласия клуба (или сразу для свободного агента /
    истекающего контракта, минуя экран клуба). Слева фото и факты игрока, согласованный fee,
    баланс после сделки и текущая зарплата (для свободного агента — приблизительная по отчёту);
    справа один столбец «зарплата / срок / амплуа / отступные» с тем же вводом суммы, что в
    продлении контракта. Игрок думает 2–4 дня и принимает, даёт до двух контрпредложений или
    отказывает; точные требования видны только в контрпредложении. Принятие контрпредложения не
    подписывает сразу: открывается финальная сводка с ручной кнопкой «Подписать», заблокированной
    при нехватке баланса. Подписание списывает fee, добавляет игрока в состав, выдаёт свободный
    номер и сразу исполняет переход, если открыто окно (1 июля–31 августа или 1–31 января); вне
    окна переход ждёт в `pending_transfers` и исполняется при открытии окна.
  - «Всемирная трансферная сеть» — отдельный экран (`Scouting.svelte`) поверх хаба: хлебные
    крошки, вкладки «Скауты / Задачи» (`L1`/`R1`), сетка 3×2 на шесть слотов, панель справа.
    Экран не скроллится; список и панель скроллятся внутри. «Скауты»: занятый скаут показывает
    «Следит за …» с прогрессом отчёта или «Просмотр региона» с числом найденных; свободный —
    «Скаут доступен»; пустой слот — «Нанять скаута». `A` на занятом открывает отчёт, на свободном —
    выбор региона. «Задачи»: по плитке на скаута (сеть страны + критерии или отчёт по игроку),
    пустая плитка — назначить задачу, слот без скаута — найм. Справа «Подробности»: найдено,
    дней работы, схема поля с зоной и список найденных игроков.
  - «Нанять скаута» — модальный экран: бюджет, таблица `Скаут / Опыт / Решение / Цена`, сортировка
    по колонкам, подтверждение «…станет вашим новым скаутом». Найм списывает цену и занимает слот.
  - «Выбор региона» → «Выбор страны» — схематичная карта сети: маркеры регионов, затем стран
    выбранного региона; слева список стран/лиг, справа карточка скаута и «Далее». Подтверждение
    «организовать здесь сеть поиска игроков» создаёт сеть и ставит скауту задачу.
  - «Задача скаута» — четыре крупные плитки «Позиция / Особенности (disabled) / Контракт / Лет»;

    автоматически по `B`/`Esc`. Справа те же «Подробности».
  - «Отчёт скаута» — вкладки «Рекомендации / Отчёты по запросу» (`L1`/`R1`), табы позиций,
    список игроков слева и карточка справа: фото, клуб, факты, OVR/потенциал, сводка, зарплата,
    стоимость и отступные. `A`/клик по игроку открывает общее окно действий
    (`PlayerActionsModal.svelte`) с раскрытыми рейтингами, статами, зарплатой и ногой; оно
    совпадает с окном из поиска, строка шортлиста работает так же, а «Удалить из отчёта» (`X`) —
    дополнительная строка в этом окне. Рекомендации пусты, пока не создана сеть.

    вратаря, чтобы поле не прыгало.

    90px показывает ровно один ряд и не перекрывает нижний ряд поля; при фокусе внутри она

    центр → меню).
  - На карточках и в шапке — кондиция и статус: усталость меняет цвет полосы ниже 50%, травма
    показывает красный `+` с типом и датой возвращения; дисквалификация на фото не помечается и
    видна в блоке доступности с числом матчей. Недоступного игрока нельзя поставить в состав; в
    шапке видна строка сезонной статистики.
- Сообщения о сохранении — всплывающая плашка внизу по центру, гаснет через 2,8 с
  (`announce()` в `App.svelte`). После матча — не отчёт по игрокам, а два полноэкранных шага:
  «Результаты дня» (все матчи тура, свой подсвечен) и «Таблица» (полная таблица после тура без
  скролла, `↑`/`↓` при смене места, `—` при сохранении позиции). Оба шага листаются `A`/`Enter`, назад —
  `Esc`; после финала симуляции `A` также ведёт в результаты. После последнего матча кнопка
  результата остаётся обычной «Продолжить»; переход в следующий сезон живёт в календаре.
- **Симуляция матча** — отдельная страница, а не overlay: шапка и хаб скрыты, нижняя легенда
  остаётся. Pre-match: счёт «VS», обе команды, по 11 стартовых и 7 запасных без номеров; справа
  сразу лента событий (пустая до старта), виджета состава соперника нет. Сама страница не
  селектится: `A`/`Enter` работает глобально, `Esc` закрывает только до старта. Старт: минута идёт
  1 в секунду, в правой панели копится лента событий (гол, пенальти, жёлтая/красная, травма,
  замена), а иконки появляются у игроков в составах; `Y`/`R` пропускает. Финал — тот же экран на
  90-й минуте с полной лентой, `A` ведёт к результатам дня; во время матча `Esc` не действует.
  Домашние игроки выровнены по левому краю, гости — по правому. «Играть» — мгновенная симуляция,
  после неё открываются те же результаты дня и таблица.
- **Центр играбелен.** Верхний виджет — минималистичный календарь: слева «Далее»/«Остановить»,
  справа месяц и год, семь дней вперёд. Текущий день с нейтральной рамкой сохраняет метку и во
  время перемотки; на дне матча — логотип соперника. После матча дата = день после матча.
  `A`/`Enter` запускает перемотку по 1 дню в секунду: дорожка дней сдвигается по горизонтали,
  повторное нажатие (`A`/`Enter`/`Esc`) останавливает и сохраняет дату. Кнопки «Симулировать до
  матча» нет — перематывает сам виджет. Без остановки перемотка встаёт на дне матча, и календарь
  заменяется двумя кнопками в ряд — «Играть» (в фокусе) и «Симуляция»; «Играть» запускает
  мгновенную симуляцию и те же результаты дня, «Симуляция» — полноэкранный таймлайн матча. Внизу
  календаря — сезон,
  турнир, тур, дома/в гостях и последние
  результаты без подписи «Форма». Пара «домашний — гостевой» клуб стоит слева и по центру между
  днями и нижней строкой. После финального тура заголовок календаря — «Перейти в следующий
  сезон»; нажатие открывает экран итогов: полная таблица дивизиона без внутреннего скролла,
  зоны повышения/вылета, кнопка «Далее». Второй шаг с анимацией показывает статус клуба
  (остались/повышение/вылет), название дивизиона следующего сезона и команды, пришедшие из лиг
  выше и ниже; крайняя лига просто не показывает одну из групп. Кнопка — «Начать новый сезон».
  Таблица в хабе — топ-5 с заменой пятой строки на клуб игрока (через разделитель), если он вне
  топ-5.
- Кнопки действий — крупные вертикальные; мелкие горизонтальные — только в нижней легенде.
- **Скролл — только внутри списков/виджетов.** `.screen` не скроллится; запасные и длинные списки
  скроллятся внутри своих панелей. Подробности игрока разбиты на страницы и не скроллятся.
- Поле рисуется по слотам снимка; фото без круглых рамок, под фото — усталость, рейтинг в плашке.
  При высоте окна ≤ 910 px карточки и радар уменьшаются, при ≤ 800 px — ещё раз, чтобы поле не
  перекрывалось.

## Потоки данных

1. **Старт карьеры.** Стартовый экран предлагает «Продолжить» (последний сейв), «Новая игра» и
   список сохранений. В новой игре клиент выбирает страну → лигу → клуб, вводит имя и гражданство
   менеджера. `POST /api/careers` создаёт `Career`, берёт состав клуба из канона, генерирует seed и
   сразу пишет сейв. Открывается хаб с составом и сводкой.
2. **Чтение.** `GET /api/careers/{id}` отдаёт полный снимок карьеры. Клиент перерисовывает экран,
   ничего не вычисляя; ручной сейв — `POST /api/careers/{id}/save`.
3. **Команда.** `POST /api/careers/{id}/actions` принимает типизированное действие. `swap`
   меняет местами двух игроков (стартовых, стартового с запасным или двух запасных; порядок
   запасных пишется в `bench`); недоступных игроков обменять нельзя. `advance` двигает дату до дня
   матча (не дальше) и восстанавливает кондицию по дням. `play` доступен в день матча, симулирует
   весь тур лиги, пишет `results` и `match.played`, обновляет усталость/травмы/карточки/статистику
   и ставит дату на день после матча. `next_season` после последнего тура показывает переход,
   применяет повышение/вылет, пересобирает календарь и сбрасывает сезонную кондицию/статистику.
   `shortlist_add`/`shortlist_remove`/`shortlist_toggle` меняют шортлист и пишут журнал.
   `transfer_offer`/`loan_offer` отправляют оффер клубу, `accept_offer_counter` принимает новые
   условия; ответы клубов приходят на `advance`/загрузке. `transfer_contract` предлагает личные
   условия, `transfer_accept_counter` принимает контрпредложение игрока, `transfer_sign` вручную
   подтверждает переход. Входящие офферы обслуживают `incoming_accept`/`incoming_refuse`/
   `incoming_counter`/`incoming_ack`. Отозвать оффер нельзя.
   Все действия сохраняют сейв и возвращают новый снимок. Тренировки и переписка — в следующих
   срезах.
4. **Время.** Клиент показывает день из снимка и анимирует по 1 дню в секунду, но каждая
   остановка — это `advance` на сервер, поэтому дата в сейве всегда совпадает с экраном. Без
   остановки перемотка встаёт на дне матча; там календарь заменяется на выбор «Играть» /
   «Симуляция». Сезон завершается, когда у клуба не остаётся матчей без результата; следующий
   сезон начинается 1 июля следующего года.
5. **Матч.** `play` — мгновенная симуляция: счёт по силе выбранного XI, кондиции и RNG; события
   того же расчёта обновляют сезонную статистику, усталость, травмы и дисквалификации.
   `GET /match` собирает pre-match составы; `POST /simulate` возвращает тот же результат с
   таймлайном (голы, ассисты, пенальти, карточки, травмы и замены). Таймлайн не хранится в сейве —
   после перезагрузки остаются счёт, кондиция и статистика. Следующий срез — полноценный
   матч-движок с влиянием схемы и тактики на события.

## Инварианты

- **Сервер — истина.** Клиент не считает правила, не хранит состояние карьеры; анимация дат —
  только отображение, остановка всегда фиксируется действием `advance`.
- **Детерминизм.** Приватный RNG от seed; порядок вызовов фиксирован; replay = seed + журнал действий
  + записанные исходы сыгранных матчей.
- **Канон только читается.** После создания карьеры `canon.db` не меняется; все дельты — в сейве.
- **Сейв — дельта.** Выводимое из seed (жеребьёвка, новости, youth) не хранится. В текущем срезе
  сейв хранит `club_id`, стартовый `player_ids`, необязательные `lineup` и `bench`, `season_start`,
  `schedule`/`results` сезона, `player_state` и `condition_date`; клубы и атрибуты — из канона.
  Календарь хранится, чтобы результаты не зависели от изменений канона; он строится при создании
  карьеры и при смене сезона. Если `lineup` нет, порядок стартовых 11 выводится сервером; если
  `bench` нет — запасные сортируются по OVR.
- **Снимок полон.** Всё для хаба и экрана состава (группы, агрегаты, клуб, менеджер, дата, seed)
  считается сервером; клиент не дублирует правила.
- **Совместимость.** Несовпадение `version` — отказ, миграций нет.

## Границы

- Домен не знает про FastAPI, Svelte, SQLite и файлы. Адаптеры — снаружи.
- Матч не знает про карьеру: на вход — сила составов, на выход — счёт. Полный `MatchOutcome`
  со строками игроков появится вместе с матч-движком.
- Мир вне страны карьеры симулируется упрощённо: результаты, таблицы, бомбардиры; без полной
  кондиции игроков.
