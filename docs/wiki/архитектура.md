# Архитектура

Статус: **карьера играбельна в пределах сезона** — канон в SQLite, read-only API, создание карьеры с
JSON-сейвом, Svelte-экраны старта, создания, хаба, состава, плана игры, календаря, симуляции матча и
итогов тура. Работают повышение/вылет, кондиция, травмы, дисквалификации и сезонная статистика.
Трансферы, кубки и тренировки ещё не начаты. Канон решений — седьмая волна
`docs/specs/2026-10-21-manager-career-decisions.md`.

## Что это

Клиент-серверный веб-прототип режима карьеры менеджера. Сервер владеет миром и симуляцией, клиент —
тонкая Svelte-оболочка. Прототип проверяет две вещи: качество симуляции карьеры и удобство UX.
3D-матч и продакшн-интеграция остаются в C++-игре; прототип возвращает только `MatchOutcome`.

## Компоненты

| Часть | Технология | Ответственность |
|---|---|---|
| `web/` | Svelte 5 + Vite | Экраны, формы, отображение снимка, отправка команд |
| `server/app.py` | Python + FastAPI | REST-слой, валидация команд, выдача снимков |
| `server/canon.py` | Python + SQLite | Read-only доступ к `canon.db` |
| `server/career/core.py` | чистый Python | `Career`, `Manager`, seed, стартовая дата, версия сейва |
| `server/career/saves.py` | Python + файлы | `SaveStore`: атомарная запись, загрузка, список, `latest`, отказ по `version` |
| `server/career/snapshot.py` | чистый Python | Снимок для клиента: клуб, менеджер, группы состава, агрегаты |
| `server/career/condition.py` | чистый Python | Кондиция, травмы, дисквалификации и сезонная статистика игроков |
| `server/career/squad.py` | чистый Python | Амплуа состава, контракты, финансы и стоимость игроков, настрой от игровых минут |
| `scripts/build_canon_db.py` | Python | Сборка `canon.db` из `data/json/` и `ratings_output.json` |
| `saves/` | JSON | По одному файлу на карьеру; `version` проверяется |
| `tests/` | pytest + JSON-фикстуры | Эталонные сценарии `seed + actions → snapshot` |

## Канон и API

- `canon.db` собирается командой `python scripts/build_canon_db.py` из `data/json/` и
  `ratings_output.json`. Скрипт ищет `ratings_output.json` в корне репозитория, затем в
  `../ratings-generator/output.json`; путь можно задать через `--ratings`.
- Таблицы: `meta`, `countries`, `leagues`, `clubs`, `players`, `national_teams`. У игрока —
  `overall`, `pot` и ровно 22 стата в JSON; свободные агенты получают гражданство и стоимость из
  рейтингов (`adjusted_mv`).
- `canon.db` в `.gitignore` и всегда пересобирается; ручных правок нет.
- API канона (`server/app.py`): `/api/meta`, `/api/countries`, `/api/leagues?country_id=`,
  `/api/clubs?league_id=|country_id=`, `/api/clubs/{id}`, `/api/clubs/{id}/players`,
  `/api/players/{id}`. Сервер не читает JSON и моки: только `canon.db`.
- API карьеры: `POST /api/careers` (клуб + имя/гражданство менеджера, seed генерируется, если не
  передан), `GET /api/careers` (список), `GET /api/careers/latest` (последний изменённый),
  `GET /api/careers/{id}` (снимок), `POST /api/careers/{id}/save` (ручной сейв),
  `POST /api/careers/{id}/actions` (команды: `swap` — обмен двух игроков; `advance` с `date` —
  перевести дату на день ближе к матчу; `play` — сыграть матч в день матча; `next_season` —
  начать следующий сезон после завершения), `GET /api/careers/{id}/match` (pre-match: составы
  обеих команд) и `POST /api/careers/{id}/simulate` (результат + таймлайн событий). Создание
  сразу пишет JSON в `saves/` — первый автосейв. У карьеры есть `league_id` и `league_club_ids`:
  дивизион и его состав, которые меняются при повышении/вылете и не теряются между сезонами.
- Сезон — `server/career/season.py`: при создании строится double round-robin календарь лиги
  (круговая ротация, чётность добивается bye) от `season_start` (1 июля), даты — недельные.
  Дома/гости чередуются по турам, у каждого клуба ровно `n-1` домашних и `n-1` гостевых матчей.
  Сейв хранит `schedule` (id, тур, дата, home/away) и `results` (счёт по fixture id). Старые сейвы
  с `schedule_version < 2` при загрузке получают исправленные home/away для несыгранных туров;
  результаты и уже сыгранные матчи не меняются. Действие `play` разрешено только в день матча,
  симулирует весь тур и переводит дату на день после матча: сила клуба — средний OVR топ-11
  состава, ожидаемые голы зависят от отношения сил и домашнего преимущества, счёт —
  пуассоновская выборка с RNG `seed + fixture_id`. Детерминированность сохраняется.
- Матч-таймлайн — `server/career/match.py`: собирает состав из 11 стартовых и 7 запасных,
  генерирует голы (включая пенальти и ассисты), жёлтые/красные карточки, травмы с типом/сроком и
  замены, сохраняя соответствие счёту. События упорядочены по минуте, игроки для событий
  выбираются из активного состава на эту минуту; RNG — `seed + fixture_id + timeline`.
- Кондиция — `server/career/condition.py`: `player_state` хранит усталость, травму (`type`,
  `until`), дисквалификацию (`matches`, `reason`) и сезонные `apps/starts/minutes/goals/assists/
  yellow/red/clean_sheets`. Те же показатели дублируются по турнирам в
  `stats_by_competition` (ключ — id турнира, сейчас лига); сухой матч получает стартовый вратарь
  при нуле пропущенных. Старые сейвы при первом снимке получают разбивку из суммарной статистики.
  Стартовые получают −35 усталости, вышедшие на замену −15, восстановление +4 в день;
  при недельном календаре это оставляет остаточную усталость после нескольких матчей подряд.
  Травма блокирует выбор, красная и 5-я жёлтая дают дисквалификацию на матч. Недоступного
  стартового заменяет лучший доступный по близости позиции (вратаря — запасной вратарь), а травма
  по ходу матча принудительно меняет игрока на ближайшего по позиции. `lineup_strength` считает
  силу по выбранному XI с учётом усталости, а не по топ-11 канона.
- Контракты и настрой — `server/career/squad.py`: при создании карьеры каждый игрок получает одно
  из пяти амплуа по рангу OVR в составе (`85/65/45/25/10%` ожидаемого игрового времени), срок
  1–5 лет по возрасту, недельную зарплату от стоимости и возраста и отступные `1.2–2.0 ×`
  стоимости. Значения детерминированы `seed + player_id` и пишутся в `player_contracts`; старые
  сейвы получают их при первом снимке. Настрой = фактические минуты к ожидаемым: после каждого
  матча доступным игрокам (без травмы и дисквалификации на старте) начисляется
  `90 × доля амплуа` в знаменатель, поэтому пропущенные из-за травмы/бана матчи его не раздувают;
  сброс сезона очищает знаменатель вместе со статистикой.
- Финансы — там же: `player_values` хранит стоимость каждого игрока, `player_ages` — возраст,
  `balance` — баланс клуба `0.25 ×` суммарной стоимости состава (не меньше 1 млн). В течение
  сезона стоимость неизменна; при `next_season` пересчитывается от стоимости, возраста (+1 год),
  OVR и минут к ожидаемым, затем возраст и новая стоимость пишутся обратно в сейв. Снимок отдаёт
  `squad.finance` (баланс, стоимость состава, недельная ведомость) и обновлённые
  `market_value`/`age` игроков.
- Снимок отдаёт `season.last_matchday`: все результаты завершённого тура, таблицу после тура и
  `delta`/`previous_position` для каждого клуба. Таблица «до тура» считается исключением всех
  матчей этого тура; в первом туре дельты нулевые.
- Время двигается только серверным действием `advance`: клиент анимирует дни по 1 в секунду, но
  каждая остановка (кнопка, день матча, `Esc`) отправляет дату на сервер и сохраняется. Перескочить
  день матча нельзя; `play` до дня матча отклоняется. `next_season` доступен только после
  последнего тура: архивирует итог в журнал, сдвигает `season_start` на год, пересобирает
  календарь, меняет состав дивизиона и очищает `results`.
- Переход сезона (`season_transition`) считает итоговую таблицу дивизиона, 3 места повышения и
  3 места вылета, определяет перемещение клуба и состав следующего дивизиона. Соседние дивизионы
  ранжируются по силе составов; для нового дивизиона отдаются списки `from_above`/`from_below`
  (кто пришёл из лиги выше и ниже) и ссылки `above`/`below`. Снимок получает `season.review` с
  таблицей, зонами и переходом; `next_season` применяет тот же расчёт и сохраняет новый
  `league_id`/`league_club_ids`.
- Снимок отдаёт `season`: `season_start`, `next` (соперник, дата, тур, дома/в гостях, сила),
  `last_result` (счёт, исход W/D/L), `form` (до 5 последних матчей), полную таблицу
  (`standings`: очки, разница, место) и `review` на завершённом сезоне (итоги, повышение/вылет,
  переход в новый дивизион). Старые сейвы без `schedule`/`results` валидны: календарь строится
  лениво и записывается при первом действии.
- Сейв — дельта: `version`, `id`, `seed`, `date`, `season_start`, `manager`, `club_id`,
  `league_id`, `league_club_ids`, `player_ids`, `lineup` (необязательный порядок стартовых 11),
  `bench` (необязательный порядок запасных), `schedule`/`schedule_version`/`results` (сезон),
  `player_state` (усталость, травмы, дисквалификации, сезонная статистика, разбивка по турнирам и
  знаменатель настроя),
  `player_contracts` (амплуа, срок, зарплата, отступные), `player_values` (стоимость),
  `player_ages` (возраст на текущий сезон), `balance`, `condition_date`, `journal`,
  `created_at`/`updated_at`.
  Клуб и атрибуты игроков не дублируются — читаются из `canon.db` при загрузке. Сейвы без
  `lineup`/`bench` валидны: стартовые выводятся из `player_ids` по схеме 4-3-3, запасные — по
  OVR. Старые сейвы без `player_state` получают усталость 100 и нулевую статистику. `version`
  сейва ≠ 1 даёт HTTP 409 с текстом «migrations are not available»; такие файлы видны в списке как
  несовместимые.
- Снимок карьеры уже содержит `club`, `manager`, `squad.groups` (по ролям, каждый игрок с 22
  статами и разбивкой `competition_stats`), `squad.summary` (размер, средний OVR/возраст,
  суммарная стоимость), `squad.finance` (баланс, стоимость, недельная ведомость),
  `squad.lineup` (схема 4-3-3: 11 слотов с координатами и игроками +
  запасные в сохранённом порядке) и `season`. В `lineup` каждый игрок приходит со `stats` (22
  стата), `fatigue`, `effective_overall`, `injury`, `suspension`, `season_stats` и `available`;
  недоступные стартовые автоматически заменяются лучшими доступными. `lineup.bench` — до 7
  заявленных запасных, `lineup.reserve` — остальные; резервные игроки тоже выбираются и
  обмениваются, но пока остаются ниже заявки, в матч не попадают. Каждый игрок состава также
  несёт `squad_role`/`squad_role_label`, `expected_share`, `actual_minutes`, `expected_minutes`,
  `morale` и `contract` (`years`, `weekly_wage`, `release_clause`). `competition_stats` — список
  турниров с `id`, `name`, играми, голами, ассистами, минутами, карточками и сухими матчами.
  Клиент только форматирует числа и рисует поле.
- Фронтенд собирается в `web/dist`, и `server.py` раздаёт его с `/`; `/raster` — статика.
- Фото игроков: `/raster/players_faces_cutout/{id}.png` — вырезанные из GameplayFootball
  (`data/databases/default/faces`); если файла нет, API отдаёт TM-фото `/raster/players_faces/{id}.jpg`.
- `pytest` проверяет количества канона, 22 стата, обогащение свободных агентов, фильтры
  «страна → лига → клуб», состав выбранного клуба, `create → save → load → snapshot`, порядок
  списка/`latest`, отказ при несовпадении `version`, календарь double round-robin с балансом
  дома/гости, шаг даты и запрет перескочить день матча, симуляцию тура и его детерминированность
  по seed, дату «день после матча», таблицу после тура, ленивый календарь старых сейвов,
  исправление home/away у старых календарей, старт нового сезона, составы 11+7, детерминированный
  таймлайн, соответствие голов счёту, статистику/усталость после матча, травмы и дисквалификации,
  восстановление по дням, замену недоступного стартового, влияние усталости на силу и дельты
  турнирной таблицы по итогам тура. Отдельно проверены пять амплуа по иерархии OVR, доли
  ожидаемых минут, настрой `факт / ожидаемо`, исключение травмированных и дисквалифицированных
  из знаменателя, сброс знаменателя на новый сезон, контракты у старых сейвов, разбивку
  статистики по турнирам, сухие матчи вратаря, восстановление разбивки у старых сейвов и её
  сброс на новый сезон. Отдельно проверены диапазон отступных, суммарные стоимость и зарплатная
  ведомость, неизменность стоимости внутри сезона и её пересчёт от возраста/OVR/минут при смене
  сезона.

## UI/UX

- Figma — визуальная правда:
  https://www.figma.com/design/sFScRV2E8CycOIf6qW2WQf/Untitled (карьера, выбор клуба, состав, главная).
- **Один фокус на экран.** Управление — геймпад (как в EA FC) или клавиатура; на экране ровно один
  `[data-nav]:focus`, остальные элементы — контекст. **Hover = selected:** наведение мыши переводит
  тот же фокус, отдельного hover-состояния нет. Меню — верхние табы, переключение `L1`/`R1`
  (`Q`/`E` на клавиатуре).
- **Нижняя легенда** показывает подсказки последнего устройства: `A`/`B`/`L1`/`R1`/`Y` или
  `Enter`/`Esc`/`Q`/`E`/`R`/`S`. Ввод определяется в `web/src/lib/input.js`, действие — в
  `actions.js`. `R`/`Y` открывают подробности игрока в плане игры.
- **Экраны:** старт (3 крупные карточки «Продолжить / Новая игра / Загрузить»), загрузка (список
  карьер), новая карьера (страна → лига → клуб-карусель → менеджер), хаб FIFA 18 (табы «Центр»,
  «Состав», далее «Трансферы / Офис / Сезон» со статусом «скоро»).
  - «Центр» — журнальная сетка виджетов FIFA: «Далее» (месяц и дни, календарь — #3), «Центр
    трансферов» (большой блок, #4), «Таблицы» (#3), «Срочные новости» (#4), «Тренировка» (#4).
    Виджетов «Состав» и «Лидеры состава» нет: состав открывается верхним табом.
  - «Состав» — обзор: слева крупная карточка «{клуб}: по умолч.» с полем, справа сетка 2×3 из
    плиток FIFA: «Состав клуба» (выбранная, с гербом и галочкой; это индикатор клуба, а не переход),
    «Сборная» (disabled), «Центр составов», «Выбор состава сборной», «Основные составы», «Изменить
    игрока» (все неготовые — disabled). `A` на карточке клуба открывает «План игры», `A` на
    «Центре составов» — одноимённый экран.
  - «Центр составов» — отдельный экран поверх хаба: главные табы карьеры скрыты, остаются бренд и
    клубная строка. Верхние вкладки «Статус / Статистика / Характеристики / Финансы» (`L1`/`R1`).
    Список состава слева общий для трёх вкладок, карточка игрока
    справа следует за фокусом; список скроллится внутри панели. «Статус» — фото, амплуа и OVR,
    настрой смайликом (улыбка / нейтральный / грустный) с процентом и фактическими/ожидаемыми
    минутами, личные данные, контракт (амплуа, срок, недельная зарплата, отступные) и доступность
    (травма, дисквалификация или «Готов к игре»). «Статистика» — суммарные игры, голы, ассисты и
    минуты в строке игрока; справа итог сезона и разбивка по турнирам с голами, ассистами,
    жёлтыми/красными и сухими матчами у вратарей. «Характеристики» — четыре страницы:
    «Общая информация» (позиция, возраст, амплуа, настрой, финты и слабая нога звёздами,
    потенциал, стоимость, контракт и значения шести осей радара), «Ментальные», «Физические» и
    «Технические», плюс сам радар. Страницы листает FIFA-пейджер (стрелки, круг `R` и точки);
    он не входит в фокус: `←`/`→` или правый стик переключают страницы, не снимая фокус с игрока,
    стрелки кликаются мышью. «Финансы» — сверху баланс клуба, стоимость состава и недельная
    зарплатная ведомость, ниже таблица игроков с фото: позиция, имя, возраст, стоимость, зарплата и
    срок контракта. Справа — карточка выбранного игрока с фото, амплуа, OVR, настроем, стоимостью,
    зарплатой, отступными, сроком и амплуа контракта, доступностью и кондицией. Фокус и навигация
    работают с клавиатуры и геймпада.
  - «План игры» — ровно половина ширины экрана (левая): вкладки плана, шапка игрока, поле и
    выезжающая снизу панель запасных. Правая половина зарезервирована под будущий состав соперника
    в экране матча, сейчас там крупный герб клуба. Шапка фиксированной высоты независимо от
    вратаря, чтобы поле не прыгало.
  - Шапка игрока: фото с полосой усталости под ним; справа — номер, имя, амплуа и рейтинг, затем
    `›` и позиция/рейтинг после обмена (у запаса, уходящего с поля, — прочерк); справа роза талантов.
    В сравнении два игрока зеркально и две розы (заливка + контур), у новых позиций стрелки ↑/↓.
    Сила состава — щит в правом верхнем углу поля: средний OVR стартовых 11; при сравнении он
    показывает силу после обмена со стрелкой ↑/↓ и возвращается к обычной после отмены/обмена.
  - Нажатие `A` на игроке выбирает его и включает лёгкую зелёную заливку; наведение/фокус на
    второго показывает сравнение и четыре лаймовых уголка. У выбранного уголки скрыты, остаётся
    заливка. Повторный `A` меняет игроков местами, `B` снимает выбор и возвращает фокус на
    выбранного.
  - Полевая карточка — общий компонент `PlayerCard.svelte` для обзора состава и плана игры: фото,
    узкая чёрная плашка «амплуа + OVR» примерно на половину ширины, фамилия с инициалом и линия
    усталости. Ширина адаптивная: 72px в высоком окне, 62px при ≤910px, 48px при ≤800px (обзор —
    80/68/54px); полоса и усталость той же ширины. Цвета амплуа — яркие по линиям (вратарь, защита,
    середина, фланги, атака). Длинная фамилия обрезается, а при наведении/фокусе прокручивается один
    полный цикл и возвращается. С любого защитника (`CB`/`LB`/`RB`) стрелка вниз ведёт на вратаря,
    только с вратаря — в запас.
  - Нижняя панель запасных — в стиле FIFA 18, но в тёмной палитре карьеры; горизонтального скролла
    нет. Игроки лежат сеткой по 4 колонки отдельным компонентом `BenchPlayerCard.svelte`: цветная
    точка и амплуа слева, голова по центру, крупный OVR справа — всё в одном ряду; линия усталости
    идёт сразу под головой, фамилия — под линией. Фокус и наведение показывают четыре лаймовых
    уголка; после нажатия уголки уходят, остаётся лёгкая полупрозрачная зелёная заливка. Игрок на
    поле выделяется так же. Верхней надписи «Запасные» нет, счётчики живут в заголовках секций.
    Свёрнутая панель высотой
    90px показывает ровно один ряд и не перекрывает нижний ряд поля; при фокусе внутри она
    раскрывается и скроллится вертикально.
    Стрелки и D-pad ходят по сетке явно: влево/вправо по соседям, вверх/вниз по колонкам.
    Секции не смешиваются: с последнего ряда запаса вниз ведёт на первого резервиста.
    Первые 7 доступных — «Запас», остальные — «Резерв». Резервные игроки выбираются и обмениваются
    как запасные; пока игрок остаётся в резерве, он не попадает в матч.
  - Подробности (`R`/`Y`) **заменяют поле и запасных**, а не выводятся сбоку: шапка остаётся, ниже —
    четыре страницы без скролла: «Общая информация», «Статы 1» (ментальные + физические), «Статы 2»
    (технические) и «Сезон» (матчи, старты, минуты, голы, ассисты, карточки). `Q`/`E` (`L1`/`R1`)
    листают страницы, точки внизу показывают текущую. В сравнении на всех страницах видны значения
    обоих игроков. `R` возвращает поле; `Esc`/`B` ведёт назад по шагам (подробности → поле → обзор →
    центр → меню).
  - На карточках и в шапке — кондиция и статус: усталость меняет цвет полосы ниже 50%, травма
    показывает красный `+` с типом и датой возвращения, дисквалификация — янтарный `!` с числом
    матчей. Недоступного игрока нельзя поставить в состав; в шапке видна строка сезонной статистики.
- Сообщения о сохранении — всплывающая плашка внизу по центру, гаснет через 2,8 с
  (`announce()` в `App.svelte`). После матча — не отчёт по игрокам, а два полноэкранных шага:
  «Результаты дня» (все матчи тура, свой подсвечен) и «Таблица» (полная таблица после тура без
  скролла, `↑`/`↓` при смене места, `—` при сохранении позиции). Оба шага листаются `A`/`Enter`, назад —
  `Esc`; после финала симуляции `A` также ведёт в результаты. После последнего матча кнопка
  результата остаётся обычной «Продолжить»; переход в следующий сезон живёт в календаре.
- **Симуляция матча** — отдельная страница, а не overlay: шапка и хаб скрыты, нижняя легенда
  остаётся. Pre-match: счёт «VS», обе команды, по 11 стартовых и 7 запасных без номеров; справа
  сразу лента событий (пустая до старта), виджета состава соперника нет. Сама страница не
  селектится: `A`/`Enter` работает глобально, `Esc` закрывает только до старта. Старт: минута идёт
  1 в секунду, в правой панели копится лента событий (гол, пенальти, жёлтая/красная, травма,
  замена), а иконки появляются у игроков в составах; `Y`/`R` пропускает. Финал — тот же экран на
  90-й минуте с полной лентой, `A` ведёт к результатам дня; во время матча `Esc` не действует.
  Домашние игроки выровнены по левому краю, гости — по правому. «Играть» — мгновенная симуляция,
  после неё открываются те же результаты дня и таблица.
- **Центр играбелен.** Верхний виджет — минималистичный календарь: слева «Далее»/«Остановить»,
  справа месяц и год, семь дней вперёд. Текущий день с нейтральной рамкой сохраняет метку и во
  время перемотки; на дне матча — логотип соперника. После матча дата = день после матча.
  `A`/`Enter` запускает перемотку по 1 дню в секунду: дорожка дней сдвигается по горизонтали,
  повторное нажатие (`A`/`Enter`/`Esc`) останавливает и сохраняет дату. Кнопки «Симулировать до
  матча» нет — перематывает сам виджет. Без остановки перемотка встаёт на дне матча, и календарь
  заменяется двумя кнопками в ряд — «Играть» (в фокусе) и «Симуляция»; «Играть» запускает
  мгновенную симуляцию и те же результаты дня, «Симуляция» — полноэкранный таймлайн матча. Внизу
  календаря — сезон,
  турнир, тур, дома/в гостях и последние
  результаты без подписи «Форма». Пара «домашний — гостевой» клуб стоит слева и по центру между
  днями и нижней строкой. После финального тура заголовок календаря — «Перейти в следующий
  сезон»; нажатие открывает экран итогов: полная таблица дивизиона без внутреннего скролла,
  зоны повышения/вылета, кнопка «Далее». Второй шаг с анимацией показывает статус клуба
  (остались/повышение/вылет), название дивизиона следующего сезона и команды, пришедшие из лиг
  выше и ниже; крайняя лига просто не показывает одну из групп. Кнопка — «Начать новый сезон».
  Таблица в хабе — топ-5 с заменой пятой строки на клуб игрока (через разделитель), если он вне
  топ-5.
- Кнопки действий — крупные вертикальные; мелкие горизонтальные — только в нижней легенде.
- **Скролл — только внутри списков/виджетов.** `.screen` не скроллится; запасные и длинные списки
  скроллятся внутри своих панелей. Подробности игрока разбиты на страницы и не скроллятся.
- Поле рисуется по слотам снимка; фото без круглых рамок, под фото — усталость, рейтинг в плашке.
  При высоте окна ≤ 910 px карточки и радар уменьшаются, при ≤ 800 px — ещё раз, чтобы поле не
  перекрывалось.

## Потоки данных

1. **Старт карьеры.** Стартовый экран предлагает «Продолжить» (последний сейв), «Новая игра» и
   список сохранений. В новой игре клиент выбирает страну → лигу → клуб, вводит имя и гражданство
   менеджера. `POST /api/careers` создаёт `Career`, берёт состав клуба из канона, генерирует seed и
   сразу пишет сейв. Открывается хаб с составом и сводкой.
2. **Чтение.** `GET /api/careers/{id}` отдаёт полный снимок карьеры. Клиент перерисовывает экран,
   ничего не вычисляя; ручной сейв — `POST /api/careers/{id}/save`.
3. **Команда.** `POST /api/careers/{id}/actions` принимает типизированное действие. `swap`
   меняет местами двух игроков (стартовых, стартового с запасным или двух запасных; порядок
   запасных пишется в `bench`); недоступных игроков обменять нельзя. `advance` двигает дату до дня
   матча (не дальше) и восстанавливает кондицию по дням. `play` доступен в день матча, симулирует
   весь тур лиги, пишет `results` и `match.played`, обновляет усталость/травмы/карточки/статистику
   и ставит дату на день после матча. `next_season` после последнего тура показывает переход,
   применяет повышение/вылет, пересобирает календарь и сбрасывает сезонную кондицию/статистику.
   Все действия сохраняют сейв и возвращают новый снимок. Трансферы, тренировки и переписка — в
   следующих срезах.
4. **Время.** Клиент показывает день из снимка и анимирует по 1 дню в секунду, но каждая
   остановка — это `advance` на сервер, поэтому дата в сейве всегда совпадает с экраном. Без
   остановки перемотка встаёт на дне матча; там календарь заменяется на выбор «Играть» /
   «Симуляция». Сезон завершается, когда у клуба не остаётся матчей без результата; следующий
   сезон начинается 1 июля следующего года.
5. **Матч.** `play` — мгновенная симуляция: счёт по силе выбранного XI, кондиции и RNG; события
   того же расчёта обновляют сезонную статистику, усталость, травмы и дисквалификации.
   `GET /match` собирает pre-match составы; `POST /simulate` возвращает тот же результат с
   таймлайном (голы, ассисты, пенальти, карточки, травмы и замены). Таймлайн не хранится в сейве —
   после перезагрузки остаются счёт, кондиция и статистика. Следующий срез — полноценный
   матч-движок с влиянием схемы и тактики на события.

## Инварианты

- **Сервер — истина.** Клиент не считает правила, не хранит состояние карьеры; анимация дат —
  только отображение, остановка всегда фиксируется действием `advance`.
- **Детерминизм.** Приватный RNG от seed; порядок вызовов фиксирован; replay = seed + журнал действий
  + записанные исходы сыгранных матчей.
- **Канон только читается.** После создания карьеры `canon.db` не меняется; все дельты — в сейве.
- **Сейв — дельта.** Выводимое из seed (жеребьёвка, новости, youth) не хранится. В текущем срезе
  сейв хранит `club_id`, стартовый `player_ids`, необязательные `lineup` и `bench`, `season_start`,
  `schedule`/`results` сезона, `player_state` и `condition_date`; клубы и атрибуты — из канона.
  Календарь хранится, чтобы результаты не зависели от изменений канона; он строится при создании
  карьеры и при смене сезона. Если `lineup` нет, порядок стартовых 11 выводится сервером; если
  `bench` нет — запасные сортируются по OVR.
- **Снимок полон.** Всё для хаба и экрана состава (группы, агрегаты, клуб, менеджер, дата, seed)
  считается сервером; клиент не дублирует правила.
- **Совместимость.** Несовпадение `version` — отказ, миграций нет.

## Границы

- Домен не знает про FastAPI, Svelte, SQLite и файлы. Адаптеры — снаружи.
- Матч не знает про карьеру: на вход — сила составов, на выход — счёт. Полный `MatchOutcome`
  со строками игроков появится вместе с матч-движком.
- Мир вне страны карьеры симулируется упрощённо: результаты, таблицы, бомбардиры; без полной
  кондиции игроков.
